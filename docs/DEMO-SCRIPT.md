# 3分で「任せられる理由」を伝える

## 一番伝えること

**AIに資産を渡さず、どのAIに・どの店で・いくらまで任せるかを本人が決める。**

検索するチャットだけで終わらせない。同じ画面で「本人の条件 → Geminiの実行 → 本人walletからの送金 → 条件を超えると停止」を見せる。Google CloudのAIが実行し、支出条件はコントラクトが強制する役割分担を説明する。

公開Amoyで2026-10-15 19:54 JSTに300 test JPYCの本人購入が成立。2 RPCでreceipt・Gateの注文ID・owner→merchantの正確なtoken移動を照合し、Cloud Runでdownload 200も確認。[証拠](evidence/public-owner-purchase.json)。これはyours Marketの購入であり、外部ECの公開購入成功を意味しない。撮影・YouTube公開・提出は別の作業。

本人の希望に合わせ、主デモを既存JPYC ECのRICE購入にする。CHEAPの通常商品を各20個へ補充済み。**撮影前に[店舗の許可と購入の操作手順](EC-RICE-DEMO.md)で公開EC購入を1件確認する。** 以下は撮る計画であり、外部ECの公開購入成功の記録ではない。

## 撮影の設定と注意点

- PCは1440×900〜1600×1000程度、ブラウザ倍率100%。ホームではGemini・許可条件・予算が同時に入る。MetaMaskは必要な署名時だけ開く。
- 初回登録は完了済みの状態から始める。約10クリックの初回設定を、購入ごとに必要な操作として見せない。今回の購入同意の署名は録画に含める。
- 既存の300円の注文はすでに支払済み。これを開くと保存済みの実行記録を見られる。**ライブの実行を撮るときだけ新しい購入を1件行う**。記録の表示を再実行と呼ばない。
- 成功場面の前後の予算は実際の値を使う。撮影のために予算や使用済み額をリセットしない。
- 上限超過の場面は「AIの1回上限2,000円・全AIの1回上限3,000円」とHIGHの許可が有効な場合の例。HIGHの10kg・2,400円を使う。確認待ちでは支払済みと表示しない。
- 上限超過の公開実機確認は撮影時に別途行う。現在の公開成功証拠は300円の通常購入。成立しない場面を編集やUI fixtureで置き換えない。
- Geminiの回答やchain確定には実時間がかかる。短縮編集する場合は「待機時間を短縮」と表示する。画面の進捗は実データから更新し、撮影のために遅延させない。
- 実行記録を見せるときは「実行ログ」を開く。技術名の読み上げは短くし、AIの行動と支出制御を中心にする。
- MetaMaskの復元用フレーズ・秘密鍵、外部AIのbearer token、メールの宛先を映さない。
- 外部EC、外部AI単体、複数AIの競合はローカル検証と公開実機確認を分けて説明する。外部ECの注文受付を実物の配送完了と呼ばない。

## yours Marketで確認する場合

既存の300円の正常購入は[証拠](evidence/public-owner-purchase.json)を確認できる。外部ECの公開購入確認前に、確認済みの経路を見せる必要がある場合は「週次ふりかえりテンプレート」数量1→支払済み→downloadを使う。例外の試験は数量7の2,100円。こちらも公開の上限超過は別途確認する。yours Marketの注文を、外部ECの接続実証とは説明しない。
