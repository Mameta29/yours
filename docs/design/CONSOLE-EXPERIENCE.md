# 依頼と、その結果が見えるワークスペース

2026-10-15。参考にしたのは[Referoの公開画面](https://refero.design/)の余白、細い区切り、文字を中心とした情報の階層。会員向けの収録画面を閲覧したという意味ではない。

## 主役にするもの

本人の資産、AIに任せた条件、実際の購入結果を同じ画面で確認できるようにする。ホームの中心はGeminiへの依頼。右に許可条件と商品一覧、上に共有予算と本人walletを置く。大きな商品イラスト、装飾の星、重複した宣伝文、ハッカソン用の装飾は除く。外部AIの登録と詳細な権限・失効は「AIと権限」に残す。

購入先を選ぶ一覧は許可店舗を初期表示し、「すべて」で接続店舗を確認できる。価格・在庫・購入時の照合は従来の実APIを使う。画面表示のための固定成功や、待ち時間を伸ばす演出は入れない。

## 実行状況の根拠

| 表示 | 根拠 |
| --- | --- |
| 依頼を受け付け | 本人の署名から発行されたmandateと作成時刻 |
| 会計を作成 | 当該mandateに結び付いた購入intent |
| 条件を確認 | 認可状態・購入監査記録。上限等の超過は追加確認として表示 |
| 支払いを確定 | intentのconfirmedと実transaction hashの両方 |
| 商品受け取り | 本人限定の注文ページと既存のdownload API |

owner限定のrun一覧にconnection/mandate/requestの識別子を含め、別の注文の進行を混ぜない。LLMの「支払済み」という文章だけでは完了表示しない。支払予定額と確定した金額を分け、送信済みhashだけでも支払済みにはしない。

実行中・送金確認中は2秒間隔、通常は8秒間隔で状態を照合する。Geminiのtool記録は応答完了後に「実行ログ」で公開する。検索中の各tool callを逐次配信する実装ではない。APIが回答する前は「依頼を確認しています」と表示する。再読み込み後の完了カードは保存された過去の実行記録であり、再実行しない。

本人walletの残高は新しい決済の確定時にも取り直す。共有予算はDBが計算した使用済み・予約中の値を使う。

## Markdownと検証

`react-markdown`と`remark-gfm`で表・リスト・強調・codeを表示。HTMLを解釈せず、出力内の画像を取得せず、不正なURLをリンクにしない。スマートフォンでは表の領域だけを横スクロールできる。

[UI確認](../evidence/workspace-browser.json)は実Chromeと明示的なHTTP fixtureによるもの。公開Geminiと実購入の証拠は[公開購入](../evidence/public-owner-purchase.json)として別に記録する。API/consoleの変更を配備するまで、新画面を公開済みとは扱わない。
