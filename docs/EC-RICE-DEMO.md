# JPYC ECのお米で実演する

## 現在の接続と検証範囲

接続は **Gemini → yoursのUCP API → JPYC EC adapter → ステージングECの公開REST API**。MCPはこの経路で使っていない。yoursはECのDBへ直接接続せず、商品APIから取得した内容を自分のCloud SQLへ検索用に保存する。カタログの再取得はリクエスト時に最大60秒のキャッシュを挟む。購入準備ではECへ改めて実予約を作り、金額・在庫・送金先を照合する。UCPを提供するのはyoursであり、ECそのものがUCP/AP2を直接提供するという意味ではない。

現在の設定はCHEAP RICE SHOPとHIGH RICE SHOPの2店舗。ステージング全店舗が自動で登録されるわけではない。他店舗には接続設定と送金先の確認が必要で、購入者もその店舗を許可する。現adapterの対象はAmoy・配送不要・variantなし・必須追加optionなしの商品。

2026-10-15、本人の補充依頼に従い、CHEAPの通常EC商品5kgを0→20個、10kgを1→20個に補充した。HIGHは各20個。在庫以外の価格・店舗設定・本人の権限は維持。ECの公開商品APIと公開yoursのUCPに反映を確認した。[補充と公開検証の記録](evidence/ec-rice-restock.json)。

**yoursが買うのは通常ECの商品と在庫。** 店舗ページに別表示される「AI購入の在庫」は、ETHGlobal時の別SKU・別経路の在庫で、今回のyours購入では使わない。今回の補充でも変更していない。

カタログの公開接続は確認済み。外部ECの公開購入は本人のMetaMask署名を伴う次の実機確認で確定する。既存の300 test JPYC購入はyours Marketの成功証拠。

下記の全件比較プロンプトも公開Geminiで確認済み。6件→1件の2ページを取得し、CHEAP 400円とHIGH 1,200円を比較して予算内のCHEAPを提案した。検索成功は注文成立とは区別する。

## 操作する順番

1. 次のタブを開く。
   - [yours](https://yours-api-110852561536.asia-northeast1.run.app)
   - [CHEAP RICE SHOP](https://stg-ec.jpyc-service.com/shops/cheap-rice-shop)
   - 必要なら[HIGH RICE SHOP](https://stg-ec.jpyc-service.com/shops/high-rice-shop)と[店舗管理画面](https://stg-admin-ec.jpyc-service.com)。
2. yoursを再読み込みし、登録済みの本人walletでAmoyへ接続する。ホーム右のMy Geminiの「権限を編集」でCHEAP / HIGHを購入許可店舗に追加する。AIの1回上限2,000、24時間5,000、全AIの1回3,000、24時間10,000を維持し、本人確認してMetaMaskの要求を承認する。右側に両店舗名が表示されれば準備完了。初回スマートアカウント設定を最初から行う必要はない。
3. Geminiへ次の文章を送る。

   > カタログの全商品を最後のページまで取得し、お米・コシヒカリの5kg商品を店名・価格・在庫の有無で表にして比較してください。1,000円以内で買える商品をおすすめしてください。

   CHEAPの5kgは400、HIGHの5kgは1,200 test JPYC。「実行ログ」を開くと実カタログ検索を確認できる。価格・在庫の説明は当日の応答に合わせる。現カタログ検索は商品名・説明の文字列検索なので、「お米5kg」だけの検索では「コシヒカリ」の商品を漏らすことがある。比較では全件取得を明示する。
4. 右の「商品を選ぶ」で **CHEAP RICE SHOPの「お米 5kg / Rice 5 kg」400円**を選ぶ。表示されなければ「すべて」を選び、許可設定も確認する。AIはMy Gemini、数量1、注文確認メールの宛先は本人が受信できるものを入力する。
5. 「署名して、この購入を任せる」を押す。新規の外部EC予約では、**店舗の注文予約の本人確認 → この購入をAIへ任せる同意**の順にMetaMaskで確認する。チャットの「買って」だけでは支払いを始めない。署名後は同じ依頼の実行状況が進むのを待つ。
6. 「注文を開く」で **支払済み・400 test JPYC・店舗で注文を受け付けました・店舗の注文番号**を確認する。「チェーン上の取引を確認」からAmoyの取引も開く。支払済みでも店舗の受付が確認中なら、同じ注文の更新を待ち、再購入しない。
7. CHEAPの店舗ページを再読み込みする。通常商品の在庫が購入数量分減ったことを、撮影前の値と比較する。今回の補充直後に1袋だけ買った場合は20→19。管理画面では同じ店舗注文番号・商品・400円の注文も確認できる。これで外部ECの注文が実際に作られたことを示す。配送不要のAmoy検証商品なので、注文受付を実物配送完了とは説明しない。
8. 制限の実演には、許可済みHIGHの10kg **2,400 test JPYC・数量1**を使う。AIの1回2,000円を超え、全AIの1回3,000円以内。購入依頼に同意しても「あなたの確認が必要です」に戻ることを実機確認する。「内容を確認」で一件だけの追加同意を示せる。この場面は追加同意に署名せず閉じてよい。

## 撮影の要点

初回設定と許可店舗の編集は撮影前に済ませる。冒頭でECの通常商品と価格・在庫を短く見せ、yoursの許可条件とGemini検索へ切り替える。購入同意後の実処理、支払い確定、EC注文番号と在庫の変化を続ける。メール宛先など個人情報は映さない。

説明は「既存ECをつなぎ、本人の資産を本人の条件の範囲でAIが使う」。技術説明には「UCPでEC接続を共通化し、AP2で本人同意を記録し、x402で支払いを連携する」を添える。今回のEC側はadapter接続であることを明確にする。

尺は[3分の撮影台本](DEMO-SCRIPT.md)を使う。公開EC購入の確認が済むまでは、成功場面を撮影済み・検証済みとは扱わない。
